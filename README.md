# Warehouse Dashboard

Локальный дашборд кладовщика для работы с заявками, календарём, задачами и курьерскими передачами оборудования.

Проект сделан как готовый каркас для GitHub-репозитория:

- **Backend:** Django + Django REST Framework + SQLite.
- **Frontend:** React + Vite + HTML5 + CSS.
- **Время:** Владивосток, `Asia/Vladivostok`, UTC+10.
- **Хранение:** локальная SQLite база `backend/db.sqlite3`.
- **Вложения:** изображения хранятся локально в `backend/media/`.

## Основные возможности

1. **Календарь крупными карточками по дням недели**
   - каждая карточка показывает день недели и дату в формате `дд.мм`;
   - можно добавить событие/задачу на конкретный день;
   - можно оставить заметку дня: что произошло или что нужно не забыть;
   - события окрашиваются по статусу.

2. **Система задач вместо простых уведомлений**
   - задача может быть без даты: для событий, которые произойдут неизвестно когда;
   - дату задачи можно назначить, изменить или убрать;
   - статусы: `не начато`, `начато`, `выполнено`;
   - к задаче можно добавлять комментарии, дата комментария ставится автоматически;
   - к задаче можно привязать одну или несколько заявок.

3. **Заявки**
   - номер заявки проверяется по формату: `В3-00516/26`;
   - общий шаблон: `БН-ННННН/НН`, где `Б` — буква, `Н` — цифра;
   - поддерживаются русские и латинские заглавные буквы в первой позиции.

4. **Курьерские посылки / передачи**
   - отдельная вкладка «Курьеры»;
   - можно добавить курьерскую доставку как специальный тип задачи;
   - указываются направление, курьер, трек-номер, откуда/куда, дата;
   - можно привязать заявки, оставлять комментарии и прикреплять картинки с компьютера.

5. **Сегодня**
   - отдельный блок показывает, что должно произойти сегодня по Владивостоку.

## Реляционная структура БД

SQLite используется как реляционная БД. Основные сущности:

| Таблица | Назначение |
|---|---|
| `api_workrequest` | Заявки с уникальным номером по формату `БН-ННННН/НН` |
| `api_task` | Задачи, уведомления, календарные события и курьерские события |
| `api_task_requests` | Связь многие-ко-многим между задачами и заявками |
| `api_comment` | Комментарии к задачам с автоматической датой |
| `api_attachment` | Файлы/картинки, прикреплённые к задачам |
| `api_daynote` | Заметки по конкретным календарным дням |

Почему так:

- заявка может относиться к нескольким задачам;
- задача может относиться к нескольким заявкам;
- комментарии и вложения отделены от задачи, чтобы не дублировать данные;
- курьерская доставка — это задача с типом `courier`, поэтому для неё работают статусы, комментарии, заявки и вложения.

## Быстрый запуск локально

### 1. Backend

```bash
cd backend
python -m venv .venv
```

Активация окружения:

Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Linux/macOS:

```bash
source .venv/bin/activate
```

Установка зависимостей и запуск:

```bash
pip install -r requirements.txt
python manage.py migrate
python manage.py runserver 127.0.0.1:8000
```

Backend будет доступен по адресу:

```text
http://127.0.0.1:8000/api/
```

### 2. Frontend

Откройте второй терминал:

```bash
cd frontend
npm install
npm run dev
```

Frontend будет доступен по адресу:

```text
http://127.0.0.1:5173
```

## Настройка API адреса

По умолчанию frontend обращается к:

```text
http://127.0.0.1:8000/api
```

Можно переопределить адрес через файл `frontend/.env.local`:

```text
VITE_API_URL=http://127.0.0.1:8000/api
```

## Проверка формата заявки

Примеры корректных номеров:

```text
В3-00516/26
A1-12345/24
Б7-00001/25
```

Некорректные:

```text
В33-00516/26
В3-516/26
В3-00516/2026
```

## Полезные команды

Создать суперпользователя Django:

```bash
cd backend
python manage.py createsuperuser
```

Открыть админку:

```text
http://127.0.0.1:8000/admin/
```

Сбросить локальную базу:

```bash
cd backend
rm db.sqlite3
python manage.py migrate
```

На Windows вместо `rm` можно удалить файл `db.sqlite3` вручную.

## Подсервис импорта выгрузки 1С

Добавлена вкладка **«База 1С»** для загрузки локальных Excel-выгрузок и построения витрин данных.

Ожидаемый порядок колонок в `.xlsx`:

1. `Дата`
2. `Счёт`
3. `Контрагент(заказчик)`
4. `грузополучатель`
5. `Услуга1`
6. `Описание работ`
7. `Количество`
8. `Статус`
9. `Штрихкод`
10. `ФИО ответственного`

Также поддерживается короткий формат из 9 колонок без `грузополучателя`.

### Что делает подсервис

- загружает `.xlsx` в локальную SQLite-БД;
- пропускает полные дубликаты строк по стабильному хэшу события;
- извлекает номер счёта из строки вида `Счет на оплату В6-05036/26 от ...`;
- классифицирует счета `В3`, `В4`, `В6` как счета нашей лаборатории;
- остальные форматы, например `ВП-...`, `М2-...`, помечает как субподряд;
- определяет нормализованный статус события;
- считает последний статус прибора актуальным;
- исключает из статистики аномальные счета: возраст 7+ дней и все текущие приборы всё ещё в статусе `Принято на склад БП/СП`.

### API

- `POST /api/onec-imports/upload/` — загрузка `.xlsx` в поле `file`.
- `GET /api/onec-events/` — просмотр и поиск событий.
- `GET /api/onec-events/?latest=1` — только актуальные события по прибору.
- `GET /api/onec-events/stats/` — витрины и инфографика.
- `GET /api/onec-events/status-choices/` — список нормализованных статусов.
